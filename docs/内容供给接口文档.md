# Tenseiing 内容供给接口文档

> 面向负责整理/提供内容（单词、句型等）的同事。目标：告诉你系统目前支持通过接口批量提交哪些内容、每种内容的字段要求，以及哪些内容类型目前系统还没有对应接口（需要先开发才能供给）。

## 一、总览：目前有哪两个接口

系统目前只有两个内容供给接口，都在 `src/app/api/import/` 下：

| 接口 | 方法 | 作用 | 目标表 |
|---|---|---|---|
| `/api/import/words` | POST | 批量导入/更新**单词** | `words` |
| `/api/import/patterns` | POST | 批量导入/更新**句型** | `sentence_patterns` |

除了这两个，**没有其他内容供给接口**。目前系统里"检测"功能一共有 4 种题型（汉字/词义/变位/句型），但汉字检测题复用的就是单词表的字段，并不是独立内容类型，所以实际上你需要关心的内容类型只有两类：**单词**和**句型**。第四节会说明还有哪些内容"看起来该有但目前系统没有对应接口"（比如歌词）。

---

## 二、鉴权方式

两个接口用的是同一套鉴权逻辑（`src/lib/importAuth.ts`），**不是**普通用户登录鉴权，是一个独立的密钥：

- 请求头需要带：`Authorization: Bearer <IMPORT_API_SECRET的值>`
- `IMPORT_API_SECRET` 是服务器环境变量，只在后端生效，不会出现在任何前端代码里

错误情况：

| 情况 | HTTP状态码 | 返回体 |
|---|---|---|
| 服务器没配置 `IMPORT_API_SECRET` | 503 | `{ "error": "服务器未配置 IMPORT_API_SECRET，导入接口已禁用" }` |
| 密钥不对 / 没带密钥 | 401 | `{ "error": "未授权：密钥不正确" }` |

拿到密钥后，用 curl 测试的示例：

```bash
curl -X POST https://你的域名/api/import/words \
  -H "Authorization: Bearer 你的IMPORT_API_SECRET" \
  -H "Content-Type: application/json" \
  -d '{ "bank_id": "...", "words": [ ... ] }'
```

## 三、接口详细说明

### 3.1 `POST /api/import/words` —— 单词批量导入

**用途**：往指定词库（`bank_id`）里批量新增或更新单词。

**幂等机制**：以 `(bank_id, surface)` 作为去重键（数据库里有唯一约束 `words_bank_surface_key`）。同一词库下 `surface`（单词原形）相同视为同一条记录，重复提交会**更新**已有行，不会产生重复数据。这意味着你可以放心地反复提交同一份内容表格，不用担心跑重了。

**请求体结构**：

```jsonc
{
  "bank_id": "词库的UUID，必填",
  "words": [
    {
      "surface": "話す",           // 必填：单词原形（含汉字）
      "reading": "はなす",          // 必填：完整假名读音，检测判分用
      "meaning_cn": "说话",         // 必填：中文释义
      "pos": "动词",                // 可选：词性自由文本，仅展示用，不驱动任何逻辑
      "verb_type": "godan",         // 可选：见下方枚举说明，动词才填
      "adj_type": null,             // 可选：见下方枚举说明，形容词才填
      "segments": [                 // 可选：振假名分段，默认写入 []
        { "text": "話", "kana": "はな" },
        { "text": "す" }
      ],
      "example": {                  // 可选：例句，默认写入 null
        "segments": [
          { "text": "友達", "kana": "ともだち" },
          { "text": "と" },
          { "text": "話", "kana": "はな" },
          { "text": "します。" }
        ],
        "cn": "和朋友说话。"
      }
    }
  ]
}
```

**字段详细说明**：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `bank_id` | 是 | string (UUID) | 目标词库ID。示例词库 JLPT N5 的固定ID是 `00000000-0000-0000-0000-000000000001`；新词库需要先手动在 `word_banks` 表插入一行（目前没有专门的"创建词库"接口，需要直接执行 SQL 或找负责数据库的同事帮忙插入） |
| `surface` | 是 | string | 单词原形，含汉字，如 "忙しい"、"話す" |
| `reading` | 是 | string | 完整假名读音（纯假名，不含汉字），如 "いそがしい"。检测判分时会拿用户输入和这个字段比较 |
| `meaning_cn` | 是 | string | 中文释义 |
| `pos` | 否 | string \| null | 词性自由文本，比如"动词"、"い形容词"、"名词"，纯展示用，**不会**被变位引擎读取判断（那是 `verb_type`/`adj_type` 的职责） |
| `verb_type` | 否 | `"godan"` \| `"ichidan"` \| `"kahen"` \| `"sahen"` \| `null` | 动词变格分类，只有动词才填，见下方"枚举说明" |
| `adj_type` | 否 | `"i"` \| `"na"` \| `null` | 形容词分类，只有形容词才填，见下方"枚举说明" |
| `segments` | 否 | 振假名分段数组 | 结构：`{ text: string, kana?: string }[]`。`kana` 缺省表示这一段本身就是假名/符号，不需要标注读音。不传则默认写入空数组 `[]`（意味着页面上这个词不会显示逐字振假名，只会整体显示） |
| `example` | 否 | 例句对象 \| null | 结构：`{ segments: 振假名分段数组, cn: string }`。不传则为 `null`（该词在学习/检测页不会展示例句） |

**`verb_type` 枚举说明**（日语动词按变格分三大类）：

- `godan`（五段动词）：词尾在"う段"五个假名间变化，如 話す/読む/買う，数量最多、规则最复杂
- `ichidan`（一段动词）：词尾固定是"る"，变形时只去掉る，词干不变，如 食べる/見る
- `kahen`（カ変动词）：仅"来る"一词，读音变化不规则，单独一类
- `sahen`（サ変动词）：仅"する"及"〇〇する"复合动词，单独一类
- 名词等不参与变位的词，`verb_type` 留空/null

**`adj_type` 枚举说明**：

- `i`（い形容词）：词尾"い"本身参与变形，如 忙しい → 忙しくない
- `na`（な形容词）：本质接近名词，靠"だ/です"变形，如 簡単 → 簡単じゃない

**⚠️ 重要提醒——这两个字段不是可有可无的**：接口层面 `verb_type`/`adj_type` 都是可选字段，不填也能成功导入，**但不填的后果是这个词不会出现在"动词/形容词变位检测"题库里**（会被当成名词一样的"不可变位词"处理，页面上也不会显示"五段动词"之类的精确标签）。这是"静默降级"，不会报错，容易被忽略。**所以你在整理动词/形容词的内容表格时，请务必确认每一条都填了对应的 `verb_type` 或 `adj_type`**，否则数据能进系统，但变位检测题库会显得内容很少。

**⚠️ 数据准确性上还有两点接口不会帮你校验，需要你自己保证**：

1. `verb_type='godan'` 的词，`reading` 结尾假名必须是 う/く/ぐ/す/つ/ぬ/ぶ/む/る 九个假名之一（日语五段动词词典形的固定收尾方式）。如果结尾不对，这条词能导入成功，但变位规则引擎在生成题目时会静默跳过它（不会崩溃，但这个词永远不会被抽到变位检测题）。
2. `verb_type='sahen'`（サ変动词）的词，`surface` 和 `reading` **必须是完整的"〇〇する"形态**（比如 "勉強する"/"べんきょうする"），不能写成裸名词形态（比如只写 "勉強"/"べんきょう"）。这是因为变位算法是从词尾去掉"する"两个假名再拼接变形后缀，如果给的是裸名词形态，算出来的读音会是错的（比如误算成"べんきします"而不是正确的"べんきょうします"）。项目里之前的示例种子数据就踩过这个坑，已经在 `supabase/seed/0002_backfill_verb_adj_type.sql` 里改正过。

**硬性校验要求（提交前必须完成，不能依赖接口兜底）**：

1. 词性栏写作“形”时，若该词为以「い」结尾的い形容词，必须显式提交 `adj_type: "i"`；不能因为原始表只写了“形”就留空。`青い`、`明るい`、`新しい` 等词应按此规则处理。
2. 任何词只有在 `surface` 和 `reading` 都以完整「する」结尾时，才允许提交 `verb_type: "sahen"`。`哀願`、`挨拶`、`案内` 等裸名词不得标为 `sahen`；如需作为动词供给，必须改成 `哀願する`、`挨拶する`、`案内する`，并同步填写完整读音。
3. 读音恰好为「する」但词形是 `擦る`、`刷る` 等普通动词时，不得按读音字符串误判为 `sahen`，应按实际词条归类为 `godan`。
4. 所有动词和形容词必须在 `verb_type`、`adj_type` 二者中填写且仅填写一个；名词、副词等不可变位词必须显式留空，不得用自由文本 `pos` 代替结构化字段。
5. 提交前必须抽查 `verb_type='godan'` 的 `reading` 末尾是否为 `う/く/ぐ/す/つ/ぬ/ぶ/む/る`。不符合者必须人工修正或降为不可变位词，不能带着已知错误上线。

**响应**：

- 成功：`200 { "imported": <number> }` （`imported` 是这次成功写入/更新的条数）
- 请求体不是合法 JSON：`400 { "error": "请求体不是合法 JSON" }`
- 缺 `bank_id`：`400 { "error": "缺少 bank_id" }`
- `words` 不是非空数组：`400 { "error": "words 必须是非空数组" }`
- 某一条缺必填字段：`400 { "error": "第 N 条缺少 surface" }`（`reading`/`meaning_cn` 同理，N 从 0 开始计数）
- `verb_type`/`adj_type` 填了非法枚举值：`400 { "error": "第 N 条 verb_type 取值不合法: xxx" }`
- 数据库写入失败：`500 { "error": "<数据库返回的原始错误信息>" }`

### 3.2 `POST /api/import/patterns` —— 句型批量导入

**用途**：批量新增或更新日语句型（用于"学习页-句型记忆"板块和"句型意义检测"题型）。

**幂等机制**：以 `pattern` 字段本身（句型文本）作为去重键（数据库唯一约束 `sentence_patterns_pattern_key`）。同一句型文本重复提交会**更新**已有行。

**请求体结构**：

```jsonc
{
  "patterns": [
    {
      "pattern": "〜てもいいです",              // 必填：句型本身
      "reading": null,                          // 可选：句型整体假名读音标注
      "meaning_cn": "表示许可，……也可以",         // 必填：中文含义/用法说明
      "explanation": "接动词て形，用于请求或给予许可", // 可选：更详细的语法说明
      "level": "N5",                            // 可选：难度分级
      "example": {                              // 可选：例句，结构同单词接口
        "segments": [
          { "text": "写真", "kana": "しゃしん" },
          { "text": "を"},
          { "text": "撮", "kana": "と" },
          { "text": "ってもいいですか。" }
        ],
        "cn": "可以拍照吗？"
      }
    }
  ]
}
```

**字段详细说明**：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `pattern` | 是 | string | 句型本身，例如 "〜てもいいです"，同时是去重键 |
| `reading` | 否 | string \| null | 句型整体的假名读音标注，如果句型含固定汉字词可以填，纯假名句型可以不填 |
| `meaning_cn` | 是 | string | 中文含义/用法说明 |
| `explanation` | 否 | string \| null | 更详细的语法说明（接续方式、使用场景等） |
| `example` | 否 | 例句对象 \| null | 结构和单词接口的 `example` 完全一致：`{ segments: 振假名分段数组, cn: string }` |
| `level` | 否 | string \| null | 难度分级，如 "N5"/"N4"，方便以后按级别筛选 |

**句型质量硬性要求**：

1. `explanation` 不能批量使用无信息量的占位文案（例如“按句型接续规则使用。”）。必须写明至少一项真实接续方式、限制条件或典型使用场景。
2. `example` 必须是与该句型语义匹配的自然日语例句，并提供准确中文翻译；不能用“这个句子使用…… ”这类模板句替代真实示例。
3. `reading` 没有可靠来源时可以为 `null`，但不得为了消除空值而臆造读音。只有经过人工校对的整体读音才能提交。

**响应**：结构和错误码和单词接口一致（`200 { "imported": N }` / `400` 字段错误 / `500` 数据库错误 / `401`/`503` 鉴权失败）。

## 四、系统里的四种检测题型分别依赖什么内容

方便你判断"我准备的内容能覆盖到哪些检测题"：

| 题型 | 页面路由 | 依赖的字段 | 说明 |
|---|---|---|---|
| 汉字检测 | `/quiz/kanji` | `words.surface` + `words.reading` | 展示汉字原形，要求输入纯假名读音。**不是独立内容类型**，复用单词表，不需要单独供给 |
| 词义检测 | `/quiz/meaning` | `words.meaning_cn` + `words.segments` | 展示带振假名的词，四选一中文释义。干扰项从其他已学单词的 `meaning_cn` 里抽，所以词库至少要有 4 个词才能正常出这道题 |
| 变位检测 | `/quiz/conjugation` | `words.verb_type` / `words.adj_type` | 只有这两个字段之一非空的词才会进入变位检测题库，抽到题后由系统内置的变位规则引擎实时算出正确答案，不需要你额外提供"变形后的答案" |
| 句型检测 | `/quiz/pattern` | `sentence_patterns.pattern` + `sentence_patterns.meaning_cn` | 展示句型文本，四选一中文含义。同理，句型库至少要有 4 条才能正常出题 |

结论：**"例句"不是一个独立的内容类型**，它是单词和句型接口里都有的 `example` 字段（内嵌 JSON 结构），随单词/句型一起提交即可，不需要单独接口提交例句。

## 五、目前系统还没有覆盖的内容类型（需要先开发才能供给）

调研代码后确认，以下内容**目前没有数据库表、没有导入接口**，如果你手上有这些内容，暂时**没有渠道直接供给**，需要先跟开发同事确认是否要新开发对应的表和接口：

- **歌词（lyrics）**：首页有一个歌词展示区（`src/components/LyricShowcase.tsx`），当前数据仍是硬编码在 `src/lib/data/lyrics.ts` 的本地静态内容。数据库里**没有** `lyrics` 表，也没有任何迁移文件涉及歌词，因此歌词不属于这两个接口的可提交类型。如果要提供真实歌词，需由开发侧维护静态文件或另行开发歌词表及导入接口；静态文件方案不支持批量/热更新。
- **听力音频**：代码库里没有找到任何音频文件、音频字段或听力相关的组件/路由，这方面完全空白。
- **独立的"汉字/读音"内容库**：汉字检测题直接复用单词表的 `surface`/`reading`，没有独立的"常用汉字表"（比如按汉字本身而非词语组织的内容），如果你想提供的是"汉字→多种读音/词组"这种更细粒度的内容，目前系统结构不支持，需要先讨论数据模型。

如果你确认要补充的正是"单词"或"句型"，直接用第三节的两个接口即可；如果是上面列的这几类，请先跟负责开发的同事对一下需求，避免整理好的内容没有地方能导进去。

## 六、上线前内容质量门槛（硬性要求）

以下检查全部通过后，内容才允许提交到生产词库；接口返回 `200` 不代表内容质量合格：

### 7.1 词汇

- `surface`、`reading`、`meaning_cn` 全部非空；同一 `bank_id` 下 `surface` 不重复。
- 所有动词/形容词均已填写正确的结构化类型；不能只填写 `pos`。
- `sahen` 必须是完整「〇〇する」词条；不得把裸名词或仅因读音为「する」的 `擦る`、`刷る` 等误标为サ変。
- 所有以「い」结尾且词性为“形”的い形容词均填写 `adj_type: "i"`。
- 五段动词读音末尾必须符合五段收尾假名规则；异常条目必须复核。
- `segments` 与 `reading` 相互一致；`example` 如存在，日语和中文必须语义对应。

### 7.2 句型

- `pattern` 唯一，`meaning_cn` 非空且能说明实际用法。
- 每条都有真实的接续/用法说明和自然例句；禁止整批使用相同兜底文案。
- `reading` 只接受人工核验的读音；不确定时保留 `null`。

### 7.3 歌词（当前无独立导入接口）

- 歌词只能通过开发侧数据文件或后续新接口进入系统，不能伪装成单词/句型提交。
- 日语歌词为主时，每首歌可收录多条摘录，但每条必须保留歌手、歌名和原始文件来源。
- 中文翻译必须是真实翻译或经过人工校对的意译；禁止使用“歌词意境：+原句”、原文重复充当翻译，或对纯外语歌词伪称中文译文。
- 无法可靠翻译的歌词可以暂缓收录，不能以占位翻译代替质量检查。

## 七、给不熟悉技术的同事的实操建议

如果你负责整理内容但不打算自己写调用接口的脚本：

1. 把内容整理成 Excel/表格，列名尽量对齐上面"字段详细说明"表格里的字段名（`surface`/`reading`/`meaning_cn`/`verb_type`/`adj_type` 等），尤其**动词/形容词一定要标注清楚是哪种类型**（五段/一段/カ変/サ変，い形容词/な形容词），漏标会导致这些词进不了变位检测题库。
2. 交给开发同事写一个小脚本把表格转成上述 JSON 格式并调用接口，或者请他们提供一个转换脚本模板由你自己跑。
3. 提交前**不需要担心重复提交**——两个接口都是幂等的（相同 `surface`/`pattern` 会更新而不是重复插入），可以放心多次提交同一份内容做修正。
