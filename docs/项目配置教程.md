# Tenseiing 项目配置教程

> 面向新加入协作的同事，目标是让你能在半小时内把项目跑起来，并了解项目的基本规则，方便后续参与开发。

## 一、项目是什么

Tenseiing 是一个日语单词/句型记忆网站，技术栈：

- **框架**：Next.js 16（App Router）+ React 19 + TypeScript
- **样式**：Tailwind CSS v4（纯 CSS 方案实现"液态玻璃"皮肤效果，没有引入额外动画库）
- **后端/数据库**：Supabase（托管 Postgres + Auth），没有自建后端服务
- **本地缓存**：IndexedDB（通过 `idb` 库），用于"本地优先"的答题记录
- **部署**：Vercel

项目功能分三大块：**记忆**（背单词）、**学习**（变位教程+句型记忆）、**检测**（汉字/词义/变位/句型四种题型）。

---

## 二、环境准备

需要预先安装：

- **Node.js**：项目没有在 `package.json` 里用 `engines` 字段强制版本，也没有 `.nvmrc`。建议使用 Node 20 LTS 或更新版本（开发环境实测用的是 Node 22）。
- **npm**：项目用 npm 管理依赖（有 `package-lock.json`），不要混用 yarn/pnpm。
- **一个 Supabase 账号**：项目数据库不是本地跑的，是连一个真实的 Supabase 云项目，所以你需要自己在 https://supabase.com/dashboard 注册并创建一个项目（免费额度够开发用）。
- **（可选）Vercel 账号**：只有要参与部署时才需要。

> 注意：本项目**没有配置 Supabase CLI 本地开发环境**（没有 `supabase/config.toml`），所以不需要装 Docker，也不能用 `supabase start` 起本地数据库。所有环境（包括你自己的开发环境）都是直接连远程 Supabase 项目的。这意味着：**建议每个人都申请一个自己的 Supabase 项目用于开发**，避免大家的测试数据互相污染同一个数据库。

## 四、创建并初始化 Supabase 项目

### 1. 新建项目

去 https://supabase.com/dashboard 创建一个新项目，记下创建时设置的数据库密码（后面不会再用到密码本身，但建议留存）。

### 2. 执行数据库迁移（SQL Editor）

项目**没有配置 Supabase CLI**，所有建表语句需要手动去 Supabase 控制台的 **SQL Editor** 里粘贴执行。仓库里的 SQL 文件在 `supabase/migrations/` 和 `supabase/seed/` 两个目录，**必须严格按以下顺序执行**（后面的文件依赖前面文件建的表/字段）：

1. `supabase/migrations/0001_init.sql` —— 建 `word_banks`（词库）、`words`（单词）、`user_word_progress`（学习进度）三张表 + 行级安全策略（RLS）
2. `supabase/migrations/0002_conjugation_patterns_attempts.sql` —— 给 `words` 表新增 `verb_type`/`adj_type` 结构化词性字段，新建 `sentence_patterns`（句型）、`quiz_attempts`（答题记录）两张表，以及对应的唯一约束、RLS 策略、表级 GRANT 权限
3. `supabase/seed/0001_jlpt_n5.sql`（**可选**，导入示例词库 JLPT N5 共 44 条） —— 依赖第 1 步的表结构
4. `supabase/seed/0002_backfill_verb_adj_type.sql`（**可选，但如果执行了第 3 步就应该执行这一步**） —— 给第 3 步导入的 44 条词回填 `verb_type`/`adj_type`，这一步依赖第 2 步新增的字段，**必须排在第 2、3 步之后**

> 表结构和字段的详细说明见另一份《内容供给接口文档》，这里不重复贴 SQL 全文。

关于第 4 步为什么必须执行（如果执行了种子数据）：种子词库里的动词/形容词如果没有回填 `verb_type`/`adj_type`，这些词就不会出现在"动词/形容词变位检测"题库里（会被当成不可变位的词晾在一边），功能上不会报错，但检测题型会显得内容很少。

关于 GRANT 权限的坑：`0002` 迁移的注释里特别提到，之前 `word_banks`/`words` 表踩过"只配置了 RLS 策略但没给角色基础 GRANT 权限"的坑，报错是 `permission denied for table`。如果你以后自己新建表，记得 RLS 策略和 `grant select/insert ... to anon, authenticated` 两者都要配。

### 3. 获取 API 密钥

回到 Supabase 控制台 **Project Settings → API**，你需要记录三个值：

- **Project URL** → 对应环境变量 `NEXT_PUBLIC_SUPABASE_URL`
- **anon public key** → 对应 `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- **service_role key** → 对应 `SUPABASE_SERVICE_ROLE_KEY`（只有你要用批量导入接口时才需要，见下文）

### 4. （可选）确认邮箱登录配置

去 **Authentication → Providers** 确认 Email 登录已启用；如果想跳过邮箱验证方便测试，可以在 **Authentication → Settings** 里关闭 "Confirm email"。

## 五、配置环境变量

复制示例文件：

```bash
cp .env.local.example .env.local
```

`.env.local.example` 的完整内容和每个变量的说明：

```env
# Supabase 项目配置
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key

# 词库/句型批量导入接口用（/api/import/words、/api/import/patterns）
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
IMPORT_API_SECRET=change-this-to-a-random-secret

# 本地测试免登录入口（生产环境不要设置）
ENABLE_DEBUG_LOGIN=true
DEBUG_TEST_EMAIL=test@local.dev
DEBUG_TEST_PASSWORD=change-this-password
```

逐项说明：

| 变量名 | 必填？ | 用途 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | **必填** | Supabase 项目地址，浏览器和服务端都会用到（`NEXT_PUBLIC_` 前缀意味着会被打进前端 bundle，属于公开信息） |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | **必填** | Supabase 匿名公钥，受行级安全策略（RLS）限制，普通用户登录会话走这个 |
| `SUPABASE_SERVICE_ROLE_KEY` | 仅用导入接口时必填 | 绕过 RLS 的管理员密钥，**只能配在服务端环境变量里，绝不能加 `NEXT_PUBLIC_` 前缀**，否则等于把管理员权限暴露给所有访问者 |
| `IMPORT_API_SECRET` | 仅用导入接口时必填 | 自定义密钥，调用 `/api/import/*` 时要在请求头带 `Authorization: Bearer <这个值>`。不设置的话导入接口会直接返回 503（拒绝服务，不是报错，是主动禁用） |
| `ENABLE_DEBUG_LOGIN` | 可选 | 设为 `true` 才会开放本地免登录测试入口 `/debug-login`，生产环境（`NODE_ENV=production`）下这个路由会直接返回 404，不受此变量影响 |
| `DEBUG_TEST_EMAIL` / `DEBUG_TEST_PASSWORD` | 配了 `ENABLE_DEBUG_LOGIN` 才需要 | 免登录入口用的测试账号，需要你先手动去 Supabase 控制台 **Authentication → Users** 创建这个账号 |

只要跑通"登录 → 记忆 → 检测"主流程，前两个变量填好就够了。

## 六、本地启动

```bash
npm run dev
```

打开 http://localhost:3000 。

**便捷方式（macOS）**：如果你配置好了 `ENABLE_DEBUG_LOGIN` 相关变量，可以直接双击仓库根目录下的 `debug-start.command`，它会自动 `npm run dev`（如果没装依赖会先 `npm install`），等服务器就绪后自动打开浏览器跳到 `/debug-login`，用测试账号自动登录，省去每次手动登录的麻烦。这个脚本和入口都只做本地测试用，生产环境不受影响。

    quiz/

      conjugation/            动词/形容词变位检测
      pattern/                句型意义检测

    api/import/words/         单词批量导入 API
    api/import/patterns/      句型批量导入 API

  lib/
    supabase/

    types.ts                    全局 TypeScript 类型定义
    conjugation.ts              动词/形容词变位规则引擎（纯函数）
    importAuth.ts               导入接口的 Bearer 鉴权
    localStore.ts               IndexedDB 本地答题记录缓存
    kana.ts                     假名工具（答案判分用的 normalizeKana）
    seededRandom.ts              每日选词用的确定性伪随机
    theme.ts                    皮肤/主题相关

  components/                 WordCard / BankSelector / Furigana / NavBar / QuizTabs /
                               KanjiQuizRunner / MeaningQuizRunner / ConjugationQuizRunner /

> **Next.js 16 命名变化提醒**：中间件文件名从以前的 `middleware.ts` 改成了 `proxy.ts`，导出函数也从 `middleware` 改成 `proxy`。仓库里还留了一个空的 `src/middleware.ts.bak` 作为历史遗留，不用管它。

路由保护逻辑在 `src/lib/supabase/middleware.ts` 里：未登录用户访问除 `/`、`/login`、`/debug-login` 之外的路径会被重定向到 `/login`；已登录用户访问 `/login` 会被重定向到 `/memorize`。

## 八、代码规范

- **中文注释要求（项目强制约定）**：每一项功能实现必须有详细的中文注释。这不是可选建议，是项目 `CLAUDE.md` 里的硬性要求，PR 里没有注释的新逻辑会被要求补充。
- **视觉样式约定**：新增按钮/卡片应使用 `.liquid-btn`/`.glass-panel` 这类既有 CSS 类和 `var(--accent)` CSS 变量，不要硬编码颜色值（比如直接写 cyan 的十六进制色号），这样才能吃到皮肤系统的主题切换效果。皮肤系统是纯 CSS 方案（backdrop-filter + CSS变量 + transform），没有引入额外动画库，皮肤选择存在 `localStorage`。
- **检测题型的性能约定**：如果要新增检测题型，应该遵循"本地判分 + 本地缓存 + 手动同步"模式（参考 `ConjugationQuizRunner.tsx` 的写法），**不要在逐题交互里直接 `await` server action**。这是因为之前词义检测每答一题要串行等两次 Supabase 网络往返，体验很卡，后来才改成全部走 IndexedDB 本地缓存，用户点导航栏"同步"按钮才批量上传。同步策略是"本地为准覆盖云端"，不是先读云端再比较合并。
- **ESLint**：用 `eslint-config-next` 的 `core-web-vitals` + `typescript` 规则集，跑 `npm run lint` 检查。配置文件是 `eslint.config.mjs`。
- **没有 Prettier**：项目没有引入 Prettier，格式化依赖编辑器自身设置，团队协作时注意格式风格尽量贴近现有代码。
- **TypeScript**：`tsconfig.json` 开了 `strict: true`，路径别名 `@/*` 指向 `./src/*`。没有单独的 `typecheck` 脚本，如果想手动做类型检查，可以跑 `npx tsc --noEmit`。

## 十、部署

项目部署在 **Vercel**：

1. 把仓库推送到 GitHub/GitLab
2. 在 https://vercel.com/new 导入该仓库
3. 在 Vercel 项目的 Environment Variables 里配置 `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. 部署，Vercel 会自动识别 Next.js 项目并执行 `next build`

`next.config.ts` 目前是默认脚手架配置，没有自定义 `output`/`rewrites`/`images` 等选项。仓库里没有 `vercel.json`。

> **提醒（README 里没写全的一点）**：如果你想让生产环境也能用批量导入接口（`/api/import/*`），需要额外在 Vercel 的环境变量里补上 `SUPABASE_SERVICE_ROLE_KEY` 和 `IMPORT_API_SECRET`，README 原文只提到了前两个公开变量。`SUPABASE_SERVICE_ROLE_KEY` 权限很高，配置时要确认 Vercel 项目的访问权限收得够紧。

## 十一、已知空白点（接手前建议了解）

- **没有测试框架**：没有单测/集成测试，改动完全靠人肉验证 + `npm run build`/`npm run lint`。
- **没有 CI**：PR 不会自动跑构建/lint，目前靠人工检查。
- **首页歌词功能是占位数据**：`src/lib/data/lyrics.ts` 现在是硬编码的示例歌词，注释里写明"待补充真实来源"，数据库里**没有**对应的表。如果要接入真实歌词内容，需要新增数据库表和相应的导入方式（当前完全空白），可以参考另一份《内容供给接口文档》里的说明。
- **没有做过真实环境端到端联调**：README 里坦诚写了"由于当前环境没有真实的 Supabase 项目，登录注册、数据读写等功能尚未做端到端联调"，只验证过 `npm run build`（占位环境变量下）和 `npm run lint`。你在自己的 Supabase 项目上跑通登录→记忆→检测全流程时，如果发现问题，欢迎记录下来同步给团队。
- **导入接口对数据一致性没有做深度校验**：比如 `verb_type='godan'` 但 `reading` 结尾假名不合规、`sahen`（サ変动词）如果没写成完整的"〇〇する"形态，都不会在导入时报错，只会在变位检测环节被静默跳过或读音出错。批量导入内容前建议先看一遍《内容供给接口文档》里关于这部分的说明。
