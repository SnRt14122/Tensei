# 性能优化验证

## 本次范围

- 保留 React Bits 玻璃透镜，首次使用非触摸指针后才加载 Three.js；减少动态效果模式不加载鼠标透镜。
- Three.js 改为 demand 绘制，鼠标不动、内容不变时停止 WebGL 绘制和纹理上传。
- 页面纹理更新合并到输入或滚动暂停后，在空闲时执行，启动间隔至少 1 秒。宽屏截图最长宽度为 1280 像素，纹理裁切仍保持原比例。
- 页面不可见时暂停背景动画，隐藏鼠标透镜，不启动新截图。
- 首页歌词首条由服务端传入，避免 hydration 不一致；完整歌词库在点击换一句时才下载。
- 记录页每页最多挂载 10 天，只有展开日期才挂载明细。筛选和导出仍涵盖选定范围内所有匹配记录，不删除历史数据。
- 记录日期转换复用 Intl.DateTimeFormat，避免逐条创建时区格式器。

本地 Next.js production build，Chromium，1280x800，空缓存，登录页。


原生 TypeScript 测试需要支持类型擦除的 Node.js 版本（本机 Node.js 26）。
另可启动生产服务后运行 `scripts/check-cursor-performance.mjs`。
通过 `PLAYWRIGHT_MODULE` 指向已有 Playwright 安装，`TEST_BASE_URL` 默认为 `http://127.0.0.1:3100`。
脚本输出截图与测量结果至 `/tmp/tensei-performance`，无需数据库凭据。

已人工核对 Chromium/Firefox 透镜、画布像素差异、移动端布局、记录分页/空结果/筛选导出，以及皮肤窗口保存栏。
本地没有 Supabase 登录配置，真实账户数据库查询未做端到端测速；本次没有改动数据库表和学习进度写入。
