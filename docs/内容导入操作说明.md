# JLPT 内容导入操作说明

`scripts/prepare_content.py` 会读取用户提供的 N5-N1 文件夹，将词汇和语法整理成接口文档规定的 JSON。脚本使用只读源文件，重复运行会覆盖 `supabase/content/` 下同名产物，不会修改原始附件。

## 生成内容

在项目根目录执行（使用项目/桌面提供的 Python 环境）：

```bash
python3 scripts/prepare_content.py
```

生成结果：

- `supabase/content/words_n1.json`：9,063 条
- `supabase/content/words_n2.json`：4,303 条
- `supabase/content/words_n3_n4.json`：2,089 条
- `supabase/content/patterns_jlpt_n1_n5.json`：392 条（N5-N3 XLS + 可稳定提取的 N1 PDF）
- `supabase/content/manifest.json`：来源、数量和已知限制

词汇 JSON 已经是 `/api/import/words` 请求体；句型 JSON 已经是 `/api/import/patterns` 请求体。缺少例句的词汇已补充为“これは……という言葉です”通用例句，缺少例句/说明的句型也已补充通用示例。句型整体 `reading` 仍保留 `null`，因为原始资料没有统一读音，自动编造会造成错误；无法提取文本的 N5/N4 词汇 PDF，以及多栏布局导致无法可靠抽取的 N2 语法 PDF，都会在 manifest 中明确列出。

## 导入顺序

1. 先在 Supabase SQL Editor 执行 `supabase/seed/0003_jlpt_content_banks.sql`，创建 N1、N2、N3-N4 词库。
2. 准备服务器环境变量 `IMPORT_API_SECRET`，按 `docs/内容供给接口文档.md` 的鉴权方式调用 `/api/import/words`，分别提交 3 个 `words_*.json`。
3. 提交 `patterns_jlpt_n1_n5.json` 到 `/api/import/patterns`。

接口是幂等 upsert，可以安全重跑。N2 原始表没有词性列，因此这些记录不会被自动标记为可变位词；需要变位检测时，请在表格中补充词性后重新生成/提交对应记录。
