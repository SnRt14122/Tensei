# JLPT 内容导入操作说明

`scripts/prepare_content.py` 会读取用户提供的 N5-N1 文件夹，将词汇和语法整理成接口文档规定的 JSON。脚本使用只读源文件，重复运行会覆盖 `supabase/content/` 下同名产物，不会修改原始附件。

## 生成内容

在项目根目录执行（使用项目/桌面提供的 Python 环境）：

```bash
python3 scripts/prepare_content.py
```

生成结果：

- `supabase/content/words_n1.json`：9,063 条（含全量真实例句重建）
- `supabase/content/words_n2.json`：4,303 条（含全量真实例句重建 + 词性写回）
- `supabase/content/words_n3_n4.json`：2,089 条（含全量真实例句）
- `supabase/content/patterns_n5_shin_standard.json`：48 条
- `supabase/content/patterns_n4_shin_standard.json`：59 条
- `supabase/content/patterns_n3_shin_standard.json`：55 条
- `supabase/content/patterns_n2_shin_standard.json`：52 条
- `supabase/content/patterns_n1_shin_standard.json`：119 条
- `supabase/content/manifest.json`：来源、数量和已知限制

词汇 JSON 已经是 `/api/import/words` 请求体；句型 JSON 已经是 `/api/import/patterns` 请求体。句型整体 `reading` 仍保留 `null`，因为原始资料没有统一读音，自动编造会造成错误。

> **`patterns_jlpt_n1_n5.json` 已废弃（2026-09-05）**：该文件 392 条数据中 192 条 `explanation` 是「按句型接续规则使用。」这类占位文案，例句是「这个句子使用〜X」模板，不能作为正式语法库使用，已从仓库删除。全部替换为上面 5 个 `patterns_*_shin_standard.json`（来源：《新版中日交流标准日本语》），如需找回旧文件可从 git 历史 commit `e80da81` 恢复，但不建议再导入。

## 导入顺序

1. 先在 Supabase SQL Editor 依次执行（若还没跑过）：
   - `supabase/seed/0003_jlpt_content_banks.sql`，创建 N1、N2、N3-N4 词库
   - `supabase/migrations/0005_sentence_pattern_tutorial_fields.sql`，给 `sentence_patterns` 增加 `lesson`/`connection`/`usage`/`notes`/`examples` 教程字段
   - `supabase/migrations/0006_progress_easy_flag.sql`，记忆页“简单词”标记
   - `supabase/migrations/0007_pattern_progress.sql`，新建 `user_pattern_progress` 表（句型学习进度）
2. 准备服务器环境变量 `IMPORT_API_SECRET`，按 `docs/内容供给接口文档.md` 的鉴权方式调用 `/api/import/words`，分别提交 3 个 `words_*.json`。
3. 依次提交 5 个 `patterns_{n5,n4,n3,n2,n1}_shin_standard.json` 到 `/api/import/patterns`。
   **注意数据形状不同**：`n5`/`n4`/`n3`/`n2` 这 4 个文件顶层就是 `{"patterns": [...]}`，可以直接把文件内容当请求体 POST；**`patterns_n1_shin_standard.json` 顶层是裸数组**（不是 `{patterns:...}`），提交前需要自己包一层，即请求体应为 `{"patterns": <n1文件的数组内容>}`，否则接口会报“patterns 必须是非空数组”。

接口是幂等 upsert，可以安全重跑。N2 原始表没有词性列，因此这些记录不会被自动标记为可变位词；需要变位检测时，请在表格中补充词性后重新生成/提交对应记录。
